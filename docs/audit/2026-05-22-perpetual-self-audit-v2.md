## V2 Backlog (prioritized)

### PR-1: Promote `MediumTierKillSwitch` contract harness to `test/conformance/shared/`

**Scope:** S  
**Audit dimension:** test-coverage (primary) + future-proofing (secondary)  
**What:** V1 PR-9 (PR #455) shipped the `MediumTierKillSwitch` interface at `src/substrate/kill-switch/medium-tier.ts` and a `runMediumTierKillSwitchContract` contract test runner at `examples/kill-switches/process-supervisor/contract.ts`. The contract runner is the right shape (same `runFooSpec(label, factory)` signature as `runAtomsSpec`, `runAuditorSpec`, `runCanonSpec`, etc.) but it lives under `examples/` instead of `test/conformance/shared/`. A second `MediumTierKillSwitch` implementation under `examples/kill-switches/<k8s|systemd|container-runtime>/` would have to either reach across into the sibling `process-supervisor/` directory to import the contract (cross-example coupling) or duplicate the harness (drift). Move the runner to `test/conformance/shared/kill-switch-spec.ts`; leave a re-export shim at the old path for one release cycle so the process-supervisor test keeps passing without churning its import.  
**Why:** Every other substrate seam (AtomStore, Canon, Notifier, Scheduler, Auditor, Principals, Embedder) ships a contract runner at `test/conformance/shared/*-spec.ts`. The kill-switch contract is the lone exception, and the placement is an accident of v1 PR-9 shipping the example reference impl in the same PR as the interface. A second adapter is exactly the case the substrate-purity canon (`dev-substrate-not-prescription`) asks the framework to prepare for; conformance harness placement is the load-bearing detail that makes "BYO impl + run the contract" the 30-second story instead of a 30-minute archaeology dive.  
**Acceptance:** `test/conformance/shared/kill-switch-spec.ts` exports `runMediumTierKillSwitchContract` with the same signature; `examples/kill-switches/process-supervisor/contract.ts` re-exports from the new location (one deprecation cycle); a new `test/conformance/kill-switch.test.ts` wires the process-supervisor as the canonical implementation, mirroring `test/conformance/atoms.test.ts` (memory adapter wired). Regression: existing `examples/kill-switches/process-supervisor/process-supervisor.test.ts` still passes via the re-export.

### PR-2: Bootstrap-script test coverage floor (19 of 27 currently zero)

**Scope:** L  
**Audit dimension:** test-coverage (primary) + governance-enforcement (secondary)  
**What:** `scripts/bootstrap-*.mjs` carries the canon-seed contract for every actor and policy LAG ships: cto-actor, code-author, pr-fix, pr-landing, autonomous-intent, deep-planning-pipeline, llm-tool-policies, operator-directives, etc. There are 27 such scripts; only 8 have a corresponding `test/scripts/bootstrap-*.test.ts`. The 19 untested bootstraps include `bootstrap-llm-tool-policies.mjs` (seeds the deny-list every actor inherits per `dev-actor-scoped-llm-tool-policy`), `bootstrap-cto-actor-canon.mjs` + `bootstrap-cpo-actor-canon.mjs` + `bootstrap-code-author-canon.mjs` + `bootstrap-pr-fix-canon.mjs` (the four authority-bearing actor canon seeds), `bootstrap-autonomous-intent-canon.mjs` (the trust-envelope policy `pol-plan-auto-approve-via-intent`), and `bootstrap-all-canon.mjs` (the meta-runner that calls every other seed). A drift in any of these silently lands a different governance posture than what the operator approved.  
**Why:** V1 PR-6 closed the `src/actors/provisioning/` coverage gap (the first-run path). Bootstrap scripts are the first-run path's quieter sibling: the operator runs `node scripts/bootstrap.mjs` (or the targeted seed scripts during a canon edit) and the substrate inherits whatever those scripts assert into the AtomStore. The 8-of-27 coverage ratio means 70% of the canon-seeding surface has no regression catcher. The full list of untested bootstraps lives in the discipline notes below.  
**Acceptance:** every `scripts/bootstrap-*.mjs` reaches >= 60% line coverage (matching the v1 PR-6 floor) via a paired `test/scripts/bootstrap-*.test.ts` that asserts (a) which atom ids the seed writes, (b) the atom content shape (priority, scope, principal_id, layer), and (c) the idempotency contract (running the seed twice over the same AtomStore writes once, supersedes the first cleanly). Test approach mirrors the eight existing bootstrap tests (e.g. `test/scripts/bootstrap-claim-contract-canon.test.ts`): in-memory host, run the seed, query the resulting atoms, assert ids + content shape. Regression: a fresh `bootstrap-all-canon.mjs` invocation against an empty AtomStore produces the exact superset of atom ids the 27 seeds claim.

### PR-3: Convergence audit on 27 bootstrap scripts (overlap, dead atoms, missing canon refs)

**Scope:** M  
**Audit dimension:** governance-enforcement (primary) + indie-floor (secondary)  
**What:** The 27 bootstrap scripts grew organically PR by PR (each new actor / policy / pipeline-stage shipped its own seed). There is no audit pass that asserts: (a) no two seeds write the same atom id with divergent content, (b) every seeded atom has at least one consumer in `src/runtime/` (dead-atom detection), (c) every consumer of a named atom id in `src/runtime/` has a matching seed, and (d) every directive in CLAUDE.md's bracketed canon section is traceable to an emitting seed. Ship `scripts/audit-bootstrap-convergence.mjs` that performs the four checks and exits non-zero on any violation. Wire it into CI alongside the existing package-hygiene + cr-precheck checks.  
**Why:** Canon is the source of truth for governance; the seeds are how canon enters the AtomStore. Without convergence enforcement, drift compounds: PR #N adds a seed for a new policy, PR #N+5 changes the consumer to read a renamed atom id, the seed and consumer drift, and nothing catches it until an operator observes "the deny rule did not fire." The v1 PR-1 work threading `expectedRevision` through 14 runtime call sites surfaced this exact class of drift: production callers had been written assuming a substrate field that did not yet exist (the lost-update window), and there was no audit pass that would have caught the divergence. The bootstrap surface deserves the same pass.  
**Acceptance:** `scripts/audit-bootstrap-convergence.mjs` produces a deterministic report (atom-id → emitting seed → consumer file:line) and exits non-zero on (a) duplicate-id divergence, (b) dead atoms (seeded, never read), (c) ghost consumers (read in src, never seeded), (d) canon-md directives whose source atom is missing. CI workflow at `.github/workflows/ci.yml` invokes the audit pass. Regression test: a vitest fixture seeds three atoms (one with a duplicate id, one dead, one valid) and asserts the audit script reports exactly the violations expected.

### PR-4: Runbook for medium-tier kill-switch tripped (10th 3am incident)

**Scope:** S  
**Audit dimension:** operator-readiness (primary) + governance-enforcement (secondary)  
**What:** V1 PR-9 (PR #455) shipped the medium-tier kill switch. When `tripAll()` fires, every armed PID is forcibly terminated; the actor loop unwinds with `haltReason='kill-switch'`; a `kill-switch-tripped` atom lands in the AtomStore. There is no runbook covering this incident class. The v0 + v1 runbook directory covers 9 named incidents; the v1 PR-7 description called out "PR-landing actor stuck" as the remaining 1-3 gap. The medium-tier kill-switch trip is a 10th incident class that did not exist when v0 enumerated the 8-10 most-common 3am incidents because the medium tier had not shipped. Add `docs/runbooks/medium-tier-kill-switch-tripped.md` following the established 5-section shape (Symptoms, Atom kinds that fire, Recovery, Prevention follow-up, Related).  
**Why:** A kill-switch trip is a high-severity event: every armed subprocess died, an actor's apply-loop halted mid-flight, and the operator has to decide whether to (a) re-arm and resume, (b) audit what triggered the trip, or (c) declare a wider emergency. Without a runbook, the operator pattern-matches from the Console activity feed, which is the failure mode the runbook directory exists to prevent per the runbook README's discipline section. Adding this runbook also adds the medium-tier kill switch row to `docs/runbooks/README.md`'s coverage table so the operator's incident-tree includes the trip as a known classification.  
**Acceptance:** `docs/runbooks/medium-tier-kill-switch-tripped.md` exists, follows the 5-section shape, names atom kinds (`kill-switch-tripped`, related `actor-halted` atoms, the optional `medium-tier-supervisor-error` if the supervisor itself failed during trip), and lists concrete recovery steps. `docs/runbooks/README.md` updates the coverage table to 10 incidents. No em-dashes anywhere (CI gate). Recovery section includes the standard "verify what tripped" probe pointing at the Console System Health page (PR #453) and the trip atom's `derived_from` chain.

### PR-5: Working agentic agent-loop reference adapter under `examples/agent-loops/`

**Scope:** L  
**Audit dimension:** indie-floor (primary) + future-proofing (secondary)  
**What:** `examples/agent-loops/` ships two adapters: `claude-code/` (the production adapter LAG dogfoods against the operator's authenticated Claude CLI) and `resume-author/` (a wrapper that adds resume-strategy semantics on top of an arbitrary inner adapter). An indie operator without a Claude CLI subscription has no working reference adapter to study or fork; the `--stub` path that v0 PR-1 signposted gets the operator through the planning loop without an agent-loop step at all (stub mode swaps the agent-loop call for a deterministic stub). A reference adapter that uses a free or self-hostable inference path (local Ollama, free-tier API, deterministic mock for tests) closes the indie-floor education gap. Build `examples/agent-loops/deterministic-mock/` as the indie-floor reference: a fully working `AgentLoopAdapter` whose `apply()` returns a deterministic completion + commitSha + branch + atoms based on the input plan, with no external API call.  
**Why:** The canon directive `dev-indie-floor-org-ceiling` says both ends are first-class. Today the indie floor has a working AtomStore (memory + file), a working planning pipeline (single-pass + agentic), and a working kill-switch (process-supervisor) but the agent-loop seam has only a production adapter. A solo developer reading the example tree to understand what a custom agent-loop looks like has to either (a) reverse-engineer `claude-code/` (which has 8 files including a stream-json parser, prompt-builder, classifier; ~1500 lines) or (b) read `resume-author/` (which is a wrapper, not a from-scratch reference). The 30-second indie story needs a from-scratch reference: ~150 lines, one file, no external deps, asserts the AgentLoopAdapter contract.  
**Acceptance:** `examples/agent-loops/deterministic-mock/` ships with a single `index.ts` (~150 lines), an `index.test.ts` exercising the AgentLoopAdapter contract through a `runAgentLoopAdapterContract` runner (this PR also creates that runner at `test/conformance/shared/agent-loop-spec.ts` mirroring the kill-switch promotion in PR-1), and a README explaining when to fork it. The deterministic-mock returns a `completed` outcome whose `commitSha` is `'mock-sha-' + plan.id` and writes a single `agent-session` atom; tests assert the contract semantics, not the mock's specific output.

### PR-6: Adapter-conformance dashboard on Console System Health

**Scope:** M  
**Audit dimension:** operator-readiness (primary) + org-ceiling (secondary)  
**What:** V1 PR-7 (PR #453) shipped 3 substrate probes on Console System Health (claim-reaper cadence, tunnel reachability, atom-store free space). The page now has 4 probe rows total (bot-identity + 3 substrate). The next-leverage addition is an "adapter conformance" row that lists, for each AtomStore + Canon + Notifier adapter the deployment has wired, whether the conformance spec passed at deploy time. The probe reads a new `<rootDir>/conformance-receipt.json` written by an `npm run conformance:capture` command that runs `vitest run test/conformance/` against the deployed adapter set and persists pass/fail per adapter. Console renders one row per adapter with status pill + last-run timestamp + deep-link to the failing test if any.  
**Why:** An org-ceiling deployment that swaps in a custom Postgres AtomStore or a Redis Notifier has no operator-visible signal that the swap respects the contract. Today the discipline is "the operator ran the conformance suite once during deployment"; there is no surface that says "the conformance suite ran THIS deploy, here is the verdict." Without that surface, a silent regression (a Postgres adapter upgrade that breaks a CAS guarantee, a Redis client version bump that changes Notifier semantics) lands in production without an operator-visible warning. The runbook tree (PR #441 + PR-4 above) is the recovery story; the System Health page is where the operator first notices.  
**Acceptance:** Console System Health adds an "Adapter Conformance" section with one row per deployed adapter (AtomStore, CanonStore, Notifier, Scheduler, Auditor, PrincipalStore, Embedder, optionally MediumTierKillSwitch + AgentLoopAdapter). Each row shows: adapter label (e.g. "file (AtomStore)"), last-run timestamp, status pill (green = all conformance cases passed, yellow = stale > 24h, red = at least one failed), and a deep-link to the failing test details. A `npm run conformance:capture` script writes the receipt JSON; the Console reads it via the same root-dir convention the existing 4 probes use. Regression: spec fixture validates the row renders all three states correctly.

### PR-8: `runActor` conformance harness covering medium-tier opt-in

**Scope:** M  
**Audit dimension:** test-coverage (primary) + governance-enforcement (secondary)  
**What:** The `runActor` driver at `src/runtime/actors/run-actor.ts` carries non-trivial behavior around the medium-tier opt-in: the kill-switch is opt-in via the `mediumTierKillSwitch?` option; `tripAll()` fires when `haltReason === 'kill-switch'`; failures during `tripAll()` log but never block the halt path; the `ActorContext.mediumTierKillSwitch` field is only attached when the caller passed one (per `exactOptionalPropertyTypes`). Today there is no conformance harness asserting that every actor consumer respects this opt-in correctly. A future actor (say, a hypothetical `quality-judge-actor`) that ignores the opt-in semantics could silently land. Build `test/conformance/shared/run-actor-spec.ts` that exercises (a) actor runs with no medium tier wired, (b) actor runs with medium tier wired and halts on STOP, (c) actor runs with medium tier wired and halts on AbortSignal, (d) the `tripAll()` failure-non-blocking contract.  
**Why:** V1 PR-9 made the seam exist; the substrate now has no asserting how it MUST be consumed. Conformance harnesses are how the substrate communicates its contract to future BYO consumers. This is the same pattern as `runAtomsSpec` (proves an adapter respects the AtomStore contract) and the kill-switch-spec the PR-1 promotes (proves a `MediumTierKillSwitch` impl respects the contract). The missing piece is the consumer-side conformance: proves an actor respects the substrate's opt-in semantics.  
**Acceptance:** `test/conformance/shared/run-actor-spec.ts` exports `runActorConformanceSpec(label, actorFactory)` that exercises (a) through (d) above. `test/conformance/run-actor.test.ts` wires the existing in-tree `PrFixActor` as the canonical consumer (PR #170 shipped it; PR #450 retrofitted resolve-outdated-threads which makes it the right reference because it now exercises medium-tier opt-in already). The harness asserts the four contract clauses; if any clause fails, the actor is non-conforming. Regression: a fixture actor that violates clause (d) (`tripAll()` failure throws and blocks halt) is detected by the spec.

### PR-10: Canon-rendering byte-equality test for `CLAUDE.md` round-trip

**Scope:** S  
**Audit dimension:** governance-enforcement (primary) + future-proofing (secondary)  
**What:** The `CanonMdManager` (`src/substrate/canon-md/`) renders the canon section of `CLAUDE.md` between the `<!-- lag:canon-start -->` and `<!-- lag:canon-end -->` markers.
